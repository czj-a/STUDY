> **语言要求：所有输出内容必须使用中文。** 包括标题、分析、总结、评价、批判、提案等全部文字输出。论文中的专业术语首次出现时用「中文（English）」格式标注，后续可直接使用中文。图表编号、公式、参考文献等学术规范内容保持原文格式。

# 重点论文 — 全面批判分析（22步，约1-2小时）

## 适用场景

- 课题方向的奠基性论文，需要全面理解并形成批判性判断
- 方法论直接借鉴的论文，需要评估方法的优劣
- 准备论文答辩时对关键参考文献的深度分析
- 基于论文提出自己的研究方向或项目提案

## 使用方式

用户提供论文 PDF 文件或完整的论文内容。依次执行以下 22 个步骤，分为七个阶段。每个阶段完成后直接在对话中展示对应模块的分析。

---

## 第一阶段：快速概览（步骤 1-6）

### 步骤 1：三句话概括
用三句话概括论文的核心主题、研究方法和主要结论。

### 步骤 2：一句话检验
用一句话向非专业读者介绍这篇论文。

### 步骤 3：章节结构
列出主要章节和小节标题，简要说明各章节内容。

### 步骤 4：核心创新点
指出 1-3 个最核心的创新点或贡献。

### 步骤 5：关键词图谱
列出 5-10 个关键词及其在论文中的重要性。

### 步骤 6：图表速览
**第一步：整理全部图表名称。** 逐一列出论文中所有图表的编号和完整标题，按出现顺序排列，标注类型（图/表）和所在页码或章节。
**第二步：重要性排序。** 将全部图表按重要性重新排序，描述前 3 个的核心信息。
**第三步：故事线判断。** 回答：仅通过图表能否还原论文故事线？

输出格式：
```
📊 图表速览：

一、图表名称清单：
| 编号 | 类型 | 标题 | 所在章节/页码 |
|------|------|------|--------------|
| Fig. 1 | 图 | [完整标题] | [章节/页码] |
| Table 1 | 表 | [完整标题] | [章节/页码] |
| ... | ... | ... | ... |

二、重要性排序（Top 3）：
1. [图表编号+标题] — [核心信息]
2. [图表编号+标题] — [核心信息]
3. [图表编号+标题] — [核心信息]

三、故事线判断：[是/否，简要说明]
```

## 第二阶段：逐章深入拆解（步骤 7-11）

### 步骤 7：引言拆解
- 论文试图解决什么问题？
- 背景是什么？如何铺垫研究问题？
- 明确提出的研究问题是什么？
- 是否概括了主要贡献？

### 步骤 8：方法拆解
- 采用了哪种或哪些研究方法？
- 如何具体执行这些方法？
- 关键变量或指标有哪些？
- 是否提到了局限性或潜在偏差？
- 是否解释了方法选择的理由？

### 步骤 9：数据与样本审视
- 数据来源是什么？是否可靠？
- 样本量是否充足？
- 是否存在选择偏差、幸存者偏差或信息偏差？
- 数据缺失如何处理？
- 时间跨度和覆盖范围是否足够？

### 步骤 10：结果拆解
- 主要研究结果有哪些？
- 描述 2-3 个关键图表的主要信息。
- 是否直接回答了研究问题？
- 是否有意外发现？
- 统计显著性说明如何？

### 步骤 11：讨论与结论拆解
- 作者如何解释结果？
- 与哪些现有研究比较？一致还是不一致？
- 研究意义是什么？
- 局限性有哪些？
- 未来研究方向是什么？
- 结论是否呼应了引言的研究问题？

---

## 第三阶段：横向关联（步骤 12）

### 步骤 12：相关文献对比
查找或回忆 2-3 篇相关论文，比较研究问题、方法和发现的异同，指出本论文的突出差异或优势。

---

## 第四阶段：批判性评估（步骤 13-18）

这是重点论文分析的核心阶段。需要以审视的眼光，对论文进行严格的学术评估。

### 步骤 13：方法批判

批判性评估研究方法：

- **优点**：方法有哪些设计上的优点？（例如：创新性、严谨性、可复现性）
- **不足**：有哪些潜在的不足或局限性？（例如：假设过强、泛化性差、控制变量不足）
- **替代方案**：是否有其他更合适的方法？为什么作者没有采用？

```
⚖️ 方法批判：
- 优点：[...]
- 不足：[...]
- 替代方法建议：[...]
```

### 步骤 14：结果可信度

评估研究结果的可信度：

- 结果的**可信度**如何？（高/中/低，理由）
- 结果是否**充分支持**了论文的结论？
- 是否存在**其他解释**的可能性？
- 结果是否可能受到**混淆变量**的影响？
- 如果换一个样本或环境，结果是否可能**无法复现**？

```
🔍 结果可信度评估：
- 可信度：[高/中/低]
- 支持结论的程度：[...]
- 其他解释可能性：[...]
- 复现性风险：[...]
```

### 步骤 15：创新性评估

评估论文的创新性和学术价值：

- 在哪些方面具有**创新性**？（理论、方法、应用、数据）
- 这种创新性在学术界或实践中具有怎样的**价值**？
- 与同领域的其他研究相比，**贡献有多大**？
- 这篇论文是否改变了该领域的某个**基本认知**或**研究范式**？

```
🚀 创新性评估：
- 创新维度：[理论/方法/应用/数据]
- 学术价值：[...]
- 贡献大小：[大/中/小，理由]
- 范式影响：[...]
```

### 步骤 16：逻辑结构分析

分析论文的论证逻辑：

- 论证是否**清晰有力**？
- 各个部分之间是否**衔接流畅**？
- 是否存在**逻辑漏洞**？（例如：循环论证、以偏概全、跳跃推理）
- 是否存在**论证薄弱**的地方？（例如：证据不充分、推理链断裂）
- 论文的**叙事线**是否连贯？

```
🧩 逻辑结构分析：
- 论证清晰度：[强/中/弱]
- 衔接流畅度：[...]
- 逻辑漏洞：[列举，或"未发现"]
- 薄弱环节：[列举]
```

### 步骤 17：反向验证

这是最强的批判性思维训练。尝试从反面审视论文：

- 如果这篇论文的**结论是错误的**，**最可能的原因**是什么？
  - 数据偏差？方法缺陷？混杂变量？样本不具代表性？
- 需要**什么样的证据**才能**推翻**这篇论文的核心结论？
- 是否存在**替代解释**，能同样好地解释观察到的结果，却导向完全不同的结论？
- 作者是否已经**排除了这些替代解释**？他们的排除是否令人信服？

```
🔄 反向验证：
- 结论错误的最可能原因：[...]
- 推翻结论所需的证据：[...]
- 替代解释：[...]
- 作者是否已排除：[是/否，理由]
```

### 步骤 18：综合优缺点

从六个维度分别评价论文的优点和缺点：

```
📋 综合评价：

| 维度 | 优点 | 缺点 |
|------|------|------|
| 研究问题 | ... | ... |
| 研究方法 | ... | ... |
| 数据质量 | ... | ... |
| 研究结果 | ... | ... |
| 讨论深度 | ... | ... |
| 结论合理性 | ... | ... |
```

## 第五阶段：知识巩固（步骤 19-20）

### 步骤 19：一页纸总结

用一页纸总结论文要点，假设向**对这个领域不太了解的同事**介绍。

### 步骤 20：应用场景

设想 2-3 个可能的应用场景，说明如何应用论文的研究成果。

---

## 第六阶段：延伸应用（步骤 21）

### 步骤 21：项目提案

基于这篇论文的研究成果，撰写一个简短的项目提案：

```
📋 项目提案：

**项目标题**：[基于论文成果的新研究方向]

**研究背景**：
[为什么这个研究方向有价值，与原论文的关系]

**研究目标**：
[具体要解决什么问题，1-3个目标]

**研究方法**：
[计划采用的方法，与原论文方法的异同]

**预期成果**：
[预期能得出什么结论或产出什么成果]

**创新点**：
[与原论文相比，本项目的创新之处]
```

## 第七阶段：持续追踪（步骤 22）

### 步骤 22：追踪清单

生成一份可执行的持续追踪清单：

```
📋 持续追踪清单：

| 追踪方向 | 具体内容 | 用途 |
|---------|---------|------|
| 📑 引用追踪 | 论文标题：[标题]；DOI：[DOI]；关键词：[关键词] | 在 Google Scholar / Semantic Scholar 设置引用提醒 |
| 👤 作者动态 | 一作：[姓名]，[机构]；通讯作者：[姓名]，[机构] | 在 Google Scholar 关注其个人主页 |
| 📊 数据集追踪 | 数据集名称：[名称] | 定期检索该数据集上的最新论文 |
| 📰 领域追踪 | 顶会/顶刊：[1.会议名 2.期刊名 3.期刊名] | 定期浏览最新目录 |
```

## 输出方式

- 默认直接在对话中完整展示全部分析，不生成或保存 Markdown、Word、PDF 等报告文件。
- 不能用报告链接、附件或简短摘要替代完整的对话正文；全部 22 步、项目提案、追踪清单及总评也必须在对话中展示。
- 内容较长时，按阶段分段连续展示，不因篇幅而省略必需模块，也不改为文件交付。
- 仅当用户明确要求导出或保存时，才生成其要求的报告文件。
- 阅读论文所需的文本提取、页面渲染等中间文件不属于报告文件；需要落盘时遵循用户指定的中间文件目录。

## 注意事项

- 批判性评估是本 Skill 的核心价值，每个评估点都需要给出**具体理由**，不能只说"好"或"不好"
- 反向验证需要真正站在反对者的角度思考，不能敷衍了事
- 项目提案要基于论文成果延伸，不能完全脱离原论文的方向
- 如果无法联网，相关文献对比和追踪清单可以基于论文引用列表中的信息来完成
- 总评部分的"对我研究的启发"需要结合用户自己的研究方向来写，如果用户未说明则留空
